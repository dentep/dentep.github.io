# Настройка раздела «Поездки»

Раздел живёт на GitHub Pages (статика), данные — в **Firebase Firestore**,
вход — через **Firebase Authentication**. Карту привязывать не надо:
всё в бесплатном тарифе Spark (Firebase Storage не используется).

```
trips/
  index.html          список поездок (тянется из базы) + форма входа
  china2026.html      план поездки в Китай
  china2026_seed.json стартовые данные (только для первого запуска)
  auth.js             общий модуль: firebase + вход + права
  style.css           общие стили
  firebase_config.js  ключи проекта
  firestore.rules     ПРАВИЛА ДОСТУПА — скопировать в консоль
  setup_users.html    разовая страница создания пользователей (потом удалить)
```

## Что нужно сделать (по порядку)

### 1. Включить вход по паролю

1. Консоль Firebase → левое меню **Authentication** → **Get started**
2. Вкладка **Sign-in method** → **Email/Password** → **Enable** → **Save**

### 2. Создать пользователей

Пользователи **уже созданы** в Auth. Осталось создать им профили с правами —
см. шаг 2б. Страница `trips/setup_users.html` делает это автоматически,
но только при открытых правилах Firestore.

| Логин | Пароль | Права |
|---|---|---|
| denis | `denis6353` | админ — видит и правит |
| dasha | `dasha7829` | админ — видит и правит |
| test  | `test1234`  | только просмотр |

> Firebase не принимает пароли короче 6 символов, поэтому 4-значные `6353`/`7829`
> не подошли — цифры сохранены, но с префиксом имени.

Внутри Firebase они хранятся как `denis@dentep.local` и `dasha@dentep.local`
(Auth требует email, поэтому короткое имя разворачивается в служебный адрес —
на странице входа вводится просто `denis`).

### 2б. Создать профили с правами (вручную, 2 минуты)

Правила запрещают запись в `users` из браузера — это сделано специально,
чтобы никто не выдал себе админа. Поэтому профили создаются в консоли:

> ⚠️ Это делается в **Firestore Database**, НЕ в Authentication.
> Диалог «Add an Email/Password user» в Authentication → Users добавляет аккаунты
> (они уже созданы) и просит email — это не то место, жми Cancel.

**Firestore Database** → вкладка **Data** → **`+ Start collection`**
**в самой левой колонке** (там, где `(default)` и список коллекций рядом с `trips`).

> ⚠️ Колонка важна. Firestore показывает путь слева направо:
> `(default)` → `trips` → `china2026`. Кнопка `Start collection` есть в каждой колонке,
> но в правых она создаёт **подколлекцию внутри поездки** — это не то.
> `users` должна встать рядом с `trips`, а не внутри `china2026`.

Collection ID: **`users`** → **Next** → и по документу на каждого.
В поле **Document ID** вставляй uid (не Auto-ID, не имя):

| Document ID | поле | тип | значение |
|---|---|---|---|
| `8b6S2avDcrU2K56B1wYxUeX5u952` | `name` | string | `denis` |
|  | `isAdmin` | **boolean** | `true` |
| `lzIpn3S9qXfIqBdaQ4SGS2c4GKF3` | `name` | string | `dasha` |
|  | `isAdmin` | **boolean** | `true` |
| `DrkWcLmkhIdWdo0vNX5EvLfVZLw2` | `name` | string | `test` |
|  | `canView` | **boolean** | `true` |

Обрати внимание: у `test` поле называется **`canView`**, а не `isAdmin`.

Document ID — это **uid** пользователя, не имя. Свежие uid всегда можно посмотреть
в **Authentication** → **Users** → колонка *User UID* (там же кнопка копирования).

Тип `isAdmin` выбирается из выпадающего списка Type и должен быть **boolean**,
а не `string`: правила сверяют с настоящим `true`, строка `"true"` не подойдёт.

Второй документ добавляется кнопкой **+ Add document** в колонке `users`.

В итоге в базе должно быть две коллекции верхнего уровня: `trips` и `users`.

### 3. Закрыть базу правилами

Это **главный шаг для защиты**. Скопируй целиком содержимое `trips/firestore.rules`
в консоль: **Firestore Database** → вкладка **Rules** → вставить → **Publish**.

Порядок важен: сначала шаг 2, потом шаг 3. Правила запрещают запись в `users`,
поэтому после публикации `setup_users.html` уже не сможет создавать профили.

### 4. Проверить и убрать за собой

1. Открой `dentep.github.io/trips/index.html` → войди как `denis` / `6353`
2. На `dentep.github.io` должна появиться кнопка **🧭 Trips** в шапке
3. **Удали `trips/setup_users.html`** — он больше не нужен

## Как устроен доступ

### Роли

| Поле в `users/{uid}` | Что даёт |
|---|---|
| `isAdmin: true` | видит поездки и **может менять** |
| `canView: true`  | видит поездки, **менять не может** |
| ничего из этого | доступа нет вообще |

У читателя страница показывает плашку «только просмотр», поля становятся
нередактируемыми, кнопки добавления выключены, кнопки удаления убраны.
Но главное — правила Firestore отклоняют от него любую запись, поэтому
снять блокировку через консоль браузера бесполезно.

Три уровня, и только последний — настоящая защита:

1. **Кнопка Trips** на главной появляется лишь у вошедшего админа (косметика)
2. **Страницы** `trips/*` показывают гейт вместо данных, если нет прав (косметика)
3. **Правила Firestore** отклоняют любое чтение и запись поездок от неадминов —
   это работает на сервере, обойти из браузера или через консоль нельзя

Правила из `firestore.rules`:

- `users/{uid}` — читать может только сам пользователь, **писать нельзя никому**
  (поэтому обычный пользователь не выдаст себе `isAdmin`)
- `trips/{id}` — читать при `isAdmin` или `canView`, **писать только при `isAdmin`**
- всё остальное закрыто

### Поменять права пользователю

Firebase Console → **Firestore Database** → коллекция `users` → нужный документ:

- сделать админом: `isAdmin` → `true`
- понизить до просмотра: `isAdmin` → `false`, добавить `canView: true`
- отобрать доступ: оба поля в `false` (или удалить документ)

Действует сразу после перезагрузки страницы.

### Добавить нового пользователя

**Authentication** → **Users** → **Add user** (email вида `имя@dentep.local`,
пароль **не короче 6 символов**), затем в **Firestore** создать документ
`users/{его uid}` с полем `name` (string) и одним из:
`isAdmin: true` (полные права) или `canView: true` (только просмотр).
Без документа прав не будет.

## Как хранятся данные

Одна поездка — один документ `trips/{id}`:

```
trips/china2026
  title, emoji, dates      мета для страницы списка
  rows[]                   дни: дата, переезд, цены, город, ссылка, заметка, статус
  candidates[]             отели на просмотр: город, ссылка, цена, комментарий
  files[]                  файлы: название + base64
```

Страница списка `trips/index.html` **ничего не хардкодит**: она читает всю коллекцию
`trips` и считает суммы, длительность, города и счётчики из `rows`.
Новая поездка появится в списке сама, как только её документ окажется в базе.

### Про файлы

Файлы лежат в том же документе в виде base64. Картинки сжимаются в браузере
(ресайз до 1600 px + JPEG), фото 5 МБ становится ~400 КБ.
Лимит документа Firestore — **1 МБ на всё**: таблица + файлы. В панели файлов
видно, сколько занято. На файл — примерно 500 КБ; PDF тяжелее надо сжать
(например ilovepdf.com) или добавить ссылкой.

Если 1 МБ станет мало — вариант подключить Blaze и Firebase Storage,
тогда лимит на файл пропадёт.

## Про ключи Firebase

`apiKey` в вебе не секрет — он всегда виден в коде страницы, так задумано у Firebase.
Доступ ограничивают правилами Firestore и паролями, а не сокрытием ключа.
